# Market Health Index V2 Note

Last updated: 2026-05-10

This note documents the exploratory market-health v2 scores generated by `scripts/modeling/run_exploratory_target_lab.py`.

The current implementation uses FRED variables already present in the production panel. It does not yet download or merge the proposed additional series `STLFSI4`, `ANFCI`, `CFNAI`, `BAMLC0A4CBBB`, or `BAMLC0A0CM`. `USEPUINDXD` is already present.

## Timing Policy

All macro variables used by the production panel are merged as the last known FRED value at or before `prediction_date`. The v2 scores inherit that timing policy. The timing audit is written to:

- `reports/data_quality/market_health_v2_timing_audit.csv`

Current timing audit status: all available component series pass with zero future-date violations.

## Thesis Use

Market-health v2 is finalized as an audited stress-regime layer for target construction, validation, and dashboard context.

Policy:

- use it for Target Lab analysis and dashboard stress/regime context;
- allow `market_stress_score_v2`, `market_health_score_v2`, `credit_stress_score`, `real_activity_pressure_score`, and `policy_uncertainty_score` as current-row features in secondary-outcome validation models;
- treat `stress_elevated_v2` primarily as the current-row sample gate for the promoted target `stress_resilience_next_4obs`;
- do not treat market-health v2 score columns as production panel feature columns;
- do not claim it replaces the existing production macro/regime variables unless the additional FRED-series gate is completed and the panel is rebuilt with full audits.

The validation gate confirms market-health v2 is scientifically usable as context, but the detailed exploratory feature reports show that firm financial condition generally dominates over market-health v2 scores in the secondary-outcome models. Therefore it should be framed as stress/regime context rather than the central explanatory factor.
